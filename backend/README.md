# Picking Lot & MasterData API — Google Apps Script Backend

This directory contains the Google Apps Script backend for the Kaapikaadu Coffee PWA.

## Files

| File | Purpose |
| ---- | ------- |
| `Code.gs` | Google Apps Script Web App implementation (doPost + doGet) |
| `masterData.test.js` | Node test harness that mocks the Apps Script environment |

---

## Endpoints

The Web App is deployed at `{VITE_API_BASE_URL}` (ends in `/exec`).

### POST — Create Picking Lot

```
POST {VITE_API_BASE_URL}
```

Handled by `doPost(e)`. Creates a Picking Lot and its PickingLotBlocks records.

### GET — MasterData

```
GET {VITE_API_BASE_URL}?resource=masterdata
```

Handled by `doGet(e)`. Returns active MasterData records.

## MasterData API

### Request

```
GET https://script.google.com/macros/s/DEPLOYMENT_ID/exec?resource=masterdata
```

### Success Response

```json
{
  "success": true,
  "data": [
    {
      "type": "BLOCK",
      "code": "BLOCK_A",
      "en": "Block A",
      "kn": "ಬ್ಲಾಕ್ A",
      "active": true,
      "sortOrder": 1
    }
  ]
}
```

### Rules

- Only **active** records are returned.
- **SortOrder** is preserved as-is (no alphabetical reordering).
- **Stable Code** values are returned; never replaced by display labels.
- English and Kannada labels are both returned.

### Error Responses

| Scenario | errorCode | message |
| -------- | --------- | ------- |
| MasterData sheet missing | `SHEET_NOT_FOUND` | `MasterData sheet not found.` |
| Required column missing | `MISSING_COLUMNS` | `MasterData sheet is missing required columns: ...` |
| Unknown resource | `INVALID_RESOURCE` | `Unknown resource requested.` |
| Unexpected error | `SERVER_ERROR` | `Something went wrong while loading data.` |

## Google Sheet Configuration
Name - Kaapikaad Coffee Processing
The spreadsheet must contain a sheet named **`MasterData`** with the following columns (header row 1):

| Column    | Required | Description                                        |
| --------- | -------- | -------------------------------------------------- |
| Type      | Yes      | MasterData category (e.g. `BLOCK`, `VARIETY`, `STATUS`) |
| Code      | Yes      | Stable internal identifier (e.g. `BLOCK_A`)        |
| English   | Yes      | English display label                              |
| Kannada   | Yes      | Kannada display label                              |
| Active    | Yes      | `TRUE`/`FALSE` — whether the record is available   |
| SortOrder | Yes      | Display ordering (numeric)                         |

The `Active` column accepts `TRUE`/`FALSE`, `true`/`false`, `1`/`0`, `YES`/`NO`, `Y`/`N`.

Example rows:

| Type    | Code     | English | Kannada   | Active | SortOrder |
| ------- | -------- | ------- | --------- | ------ | --------: |
| BLOCK   | BLOCK_A  | Block A | ಬ್ಲಾಕ್ A  | TRUE   | 1         |
| BLOCK   | BLOCK_B  | Block B | ಬ್ಲಾಕ್ B  | TRUE   | 2         |
| VARIETY | SLN6     | SLN6    | ಎಸ್ಎಲ್ಎನ್ 6 | TRUE   | 1         |
| STATUS  | CREATED  | Created | ರಚಿಸಲಾಗಿದೆ | TRUE   | 1         |

### PickingLots Sheet

The `PickingLots` sheet must have these columns (header row 1, in order):

| Column          | Stored As | Description                                      |
| --------------- | --------- | ------------------------------------------------ |
| LotID           | Text      | Generated by the backend (`PLYYMMDD0001`)        |
| HarvestDate     | Date      | Date cherries were harvested                     |
| Block           | Text      | Selected block codes, comma-separated            |
| Variety         | Code      | Coffee variety code (e.g. `SLN6`)                |
| Process         | Code      | Selected processing method code (e.g. `NATURAL`) |
| CherryWeightKg  | Number    | Total combined cherry weight                     |
| CreatedDateTime | DateTime  | Generated by the backend                         |
| CreatedBy       | Text      | Generated by the backend                         |
| Status          | Code      | Always `CREATED`                                 |

The normalized `PickingLotBlocks` sheet records one row per selected Block (`LotID`, `BlockCode`).

## API Logging

Every API request body and response is registered in two places:

### 1. `ApiLog` sheet (production)

The Apps Script appends one row per `doPost`/`doGet` call to an **`ApiLog`** sheet in the spreadsheet (created automatically on first call):

| Column        | Contents                                            |
| ------------- | --------------------------------------------------- |
| Timestamp     | When the call was received                          |
| Method        | `POST` or `GET`                                     |
| Endpoint      | e.g. `/exec` or `/exec?resource=masterdata`         |
| RequestBody   | JSON of the request body / query parameters         |
| ResponseBody  | JSON of the response payload (success or error)     |

Logging runs in a `finally` block and never throws, so it cannot break the API response.

### 2. `logs/api.log` (local test runs)

Running `node backend/masterData.test.js` (re)creates **`logs/api.log`** and appends one JSON line per mocked API call with the timestamp, method, endpoint, request body, and response body.

> Note: `logs/` and `*.log` are git-ignored, so this file stays local.

## Deployment Steps

The Apps Script project is **container-bound** to the spreadsheet (it lives inside the Google Sheet), so you deploy from the spreadsheet itself.

1. **Open the Apps Script editor**
   - Open the Google Sheets spreadsheet (the one with the `PickingLots`, `MasterData`, `PickingLotBlocks` tabs).
   - Menu: **Extensions → Apps Script**.
   - This opens the script editor bound to that spreadsheet.

2. **Replace the script contents**
   - In the editor, open the `Code.gs` file (it may contain the default `function myFunction() {}` or an older version).
   - Delete all existing content.
   - Paste the entire contents of `backend/Code.gs`.
   - **Save** (Ctrl+S or the disk icon).

3. **Deploy as a Web App**
   - Click **Deploy** (top right) → **New deployment**.
   - Next to "Select type", click the **gear icon** and choose **Web app**.
   - Give it a **Description** (e.g. `Kaapikaadu Picking Lot API`).
   - **Execute as**: `Me`
   - **Who has access**: `Anyone`
   - Click **Deploy**.

4. **Authorize the script** (first time only)
   - A pop-up asks for permissions — choose your Google account.
   - If Google shows "This app isn't verified", click **Advanced → Go to `<project>` (unsafe) → Allow**.
   - This is expected for personal scripts; it grants access to the spreadsheet and to `Session.getActiveUser().getEmail()` (CreatedBy).

5. **Copy the Web App URL**
   - The deployment dialog shows a URL ending in `/exec`
     (e.g. `https://script.google.com/macros/s/AKfycb.../exec`).
   - Copy it.

6. **Point the frontend at it**
   - In `frontend/.env`, set:
     ```env
     VITE_API_BASE_URL=https://script.google.com/macros/s/PASTE_YOUR_ID/exec
     ```
   - Keep `VITE_APP_LANGUAGE=en` (or `kn` for Kannada).
   - Restart the Vite dev server (stop with Ctrl+C, then `npm run dev`) — `.env` is read at startup.

### Updating an already-deployed URL (important)

When you **change the code later**, saving the script alone is NOT enough — a Web App deployment keeps serving the version it was created with. To push updates:

1. **Deploy → Manage deployments**.
2. Click the **pencil (Edit)** on the existing Web App deployment.
3. Under **Version**, choose **New version**.
4. Click **Deploy**.

The URL stays the same, but now serves the new code. (If you create a new deployment instead and get a different URL, update `VITE_API_BASE_URL` in `frontend/.env` and restart Vite.)

### Verify after deployment

1. **MasterData (GET)** — open in a browser:
   ```
   https://script.google.com/macros/s/PASTE_YOUR_ID/exec?resource=masterdata
   ```
   You should see a JSON response with the active `BLOCK` / `VARIETY` records.

2. **Create a Picking Lot (POST)** — save a Picking Lot from the PWA, then check the spreadsheet:
   - `PickingLots` tab — new row with `Block`, `Variety`, `CherryWeightKg`, `Status = CREATED`.
   - `PickingLotBlocks` tab — one row per selected block.
   - `ApiLog` tab — a `POST` row containing the full request body and response.

### Troubleshooting

| Symptom | Fix |
| ------- | --- |
| Browser redirects to `script.google.com` (no JSON) | Re-run step 4 (authorize) or open the Apps Script editor and run any function once to trigger authorization. |
| `You do not have permission to call Session.getActiveUser()` | Re-deploy with **Execute as: Me** and authorize (step 4). |
| Sheet rows still show old/blank columns | The deployment is serving an old version — follow **Updating an already-deployed URL** above. |
