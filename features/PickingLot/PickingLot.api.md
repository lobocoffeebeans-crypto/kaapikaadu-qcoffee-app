# Picking Lot API Contract

## Version

v1.0

---

## Endpoint

POST /api/pickinglots

---

## Description

Creates a new Picking Lot.

The backend generates:

- Lot ID
- Status
- Created DateTime
- Created By

---

## Request Body

| Field | Type | Required | Description |
|--------|------|----------|-------------|
| harvestDate | Date | Yes | Date cherries were harvested |
| varietyCode | String | Yes | Coffee variety code |
| totalCherryWeightKg | Number | Yes | Total combined cherry weight |
| blockCodes | Array<String> | Yes | One or more selected blocks |

### Example Request

{
  "harvestDate":"2026-08-03",
  "varietyCode":"SLN6",
  "totalCherryWeightKg":320,
  "blockCodes":[
      "BLOCK01",
      "BLOCK03",
      "BLOCK05"
  ]
}

---

## Success Response

HTTP 201

{
    "success":true,
    "lotId":"PL2608030001",
    "status":"CREATED",
    "message":"Picking Lot created successfully."
}

---

## Validation Errors

### Invalid Harvest Date

HTTP 400

{
    "success":false,
    "errorCode":"INVALID_HARVEST_DATE",
    "message":"Harvest Date cannot be in the future."
}

---

### Invalid Variety

HTTP 400

{
    "success":false,
    "errorCode":"INVALID_VARIETY",
    "message":"Select a valid coffee variety."
}

---

### No Block Selected

HTTP 400

{
    "success":false,
    "errorCode":"BLOCK_REQUIRED",
    "message":"At least one block must be selected."
}

---

### Invalid Weight

HTTP 400

{
    "success":false,
    "errorCode":"INVALID_WEIGHT",
    "message":"Weight must be greater than zero."
}

---

## Business Rules

- Lot ID is generated by the backend.
- Status is always CREATED.
- Created DateTime is generated by the backend.
- Created By is generated by the backend.
- Process is not captured.
- Tank is not captured.
- Yeast is not captured.

---

## Notes

The frontend must never generate:

- Lot ID
- Status
- Created DateTime
- Created By
